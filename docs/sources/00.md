PROJECT CHARTER — Python AI Agent Runtime Framework
Version: 0.1 | 27 October 2026
Status legend: DECIDED = explicitly agreed; PROPOSED = design recommendation; OPEN = needs validation.


VISION (DECIDED)
Create a general-purpose Python framework for running and orchestrating AI agents, with coding agents as the first-class initial use case. It is a reusable runtime library, not a single fixed coding assistant.


ARCHITECTURAL PRINCIPLES (DECIDED)
• Harness-agnostic: adapters isolate agent execution backends.
• Modular, extensible and replaceable components; each agent and MCP integration can live in its own module.
• Explicit inputs/outputs; testable boundaries; maintainable separation of concerns.
• Security-first: permission check before tool execution, least privilege, safe failure semantics.
• Reliable orchestration: structured state, logs, timeouts, retries and error classification.
• Avoid heavyweight frameworks until justified.


PROPOSED MVP
A single task executes through an AgentAdapter, first with a FakeAgent, then one real ACP agent, then an optional CLI delegate relay. Return a typed TaskResult, log transitions and support cancel/timeout. Keep core independent from each transport.


DECISION REGISTER
D-001 DECIDED: Python implementation.
D-002 DECIDED: general-purpose runtime; coding agents priority.
D-003 DECIDED: harness-agnostic adapter pattern.
D-004 DECIDED: modular agents and MCP integrations.
D-005 PROPOSED: use ACP via official Python SDK as first real transport adapter.
D-006 PROPOSED: model Ahmed El Nagdy's Delegate Skills as an optional orchestration/CLI adapter or integration; do not make it the core.
D-007 PROPOSED: keep execution separate from review/approval and prevent auto-commit by default.
D-008 OPEN: project package name, license, API stability and persistence backend.


NON-GOALS FOR FIRST MILESTONE (PROPOSED)
Full multi-agent swarm, dashboard, hosted service, distributed queues, provider-specific agent behavior, autonomous pushes/commits, arbitrary MCP marketplaces.
